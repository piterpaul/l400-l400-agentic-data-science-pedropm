# Data Science & Methodological Standards
**Trigger:** Read this file whenever you are designing `DESIGN.md`, writing feature engineering SQL, splitting train/evaluation cohorts, or evaluating a Tier 1 / Tier 2 model.

## 🎯 1. Tier Discipline (No Architectural Theatre)
- **Stay inside the committed rung:** Only build the architectural tier (`Tier 1` or `Tier 2`) defended in `docs/discovery-pack.md` (Section 6) and `DESIGN.md`. Never introduce Tier 3 real-time serving infrastructure (Bigtable, Vertex Online Prediction endpoints) unless explicitly required.
- **Runtime & Cohort Parity Bounds (60–90s Budget):** When querying large public datasets, always apply the cohort/window bounds specified in `docs/discovery-pack.md` Section 7:
  - `forecasting` (`new_york_citibike.citibike_trips` & `citibike_stations`): Build a birth-aware `start_station_id × usertype` calendar spine (`trip_date >= station_first_date` across all active stations, `~926k` rows) in BigQuery SQL joined with `citibike_stations` (`capacity`, `latitude`, `longitude`), causal `station_customer_share` ratio (`ROWS BETWEEN 36 PRECEDING AND 30 PRECEDING`), horizon-safe lags (`lag_30d`, `lag_37d`), `ml_datasets.holidays_and_events_for_forecasting`, and cleaned `noaa_gsod.gsod2013..gsod2016` weather (note: in `gsod2013..gsod2016` the station ID column is `stn`, joined to `noaa_gsod.stations.usaf`, with string `year, mo, da`).
  - `search-conversion` & `recommender` (`thelook_ecommerce.products`): Filter `AI.GENERATE_TABLE` / `AI.GENERATE_EMBEDDING` to a single department or 2,500-item deterministic slice.
  - `clinical-risk` (`fhir_synthea`): Filter inpatient encounters (`class.code = 'IMP'`) to a 50,000-stay cohort and split strictly by `patient_id`.

## ⏱️ 2. Point-in-Time Features & Leak-Free Splits (CRITICAL)
- **Never use random splits on temporal or longitudinal data.**
  - For time series and transactional logs (`forecasting`, `payment-fraud`, `churn`, `next-best-offer`, `recommender`, `marketing-measurement`, `predictive-maintenance`), always split on an explicit observation cut-off timestamp or date.
  - For longitudinal patient records (`clinical-risk`), always group train/evaluation splits by `patient_id` so the same patient never appears in both train and test sets, and compute features strictly as of each admission's discharge timestamp.
- **Explicit Calendar Spine for Time Series:** Never pass raw event tables with missing dates directly to `AI.FORECAST`, `AI.DETECT_ANOMALIES`, `AI.EVALUATE`, or `ARIMA_PLUS_XREG`. Always profile temporal coverage first (`MIN(DATE(starttime))`, `MAX(DATE(starttime))`, `COUNT(DISTINCT DATE(starttime))` vs. `DATE_DIFF(MAX, MIN, DAY) + 1`) to discover any contiguous feed window and missing calendar dates (such as multi-day blizzard/weather shutdowns), then join against `GENERATE_DATE_ARRAY` and `COALESCE(value, 0)` (or forward-fill where domain-appropriate) so missing dates are explicit.

## 📊 3. Mandatory Baseline Comparison
- Every Tier 1 or Tier 2 build MUST record its primary evaluation metric side-by-side against a Tier 0 baseline on the exact same held-out evaluation split in `<project>.<dataset>.eval_comparison`:
  - **Time Series (`forecasting`):** Compare `ARIMA_PLUS_XREG` or pooled `BOOSTED_TREE_REGRESSOR` / LightGBM against zero-shot `AI.EVALUATE` (`TimesFM 2.5` univariate baseline) and/or `AI.FORECAST` (`TimesFM 3.0` Preview with covariates).
  - **Tabular Classification / Propensity (`next-best-offer`, `payment-fraud`, `churn`, `clinical-risk`, `predictive-maintenance`):** Compare `BOOSTED_TREE_CLASSIFIER` / survival model against zero-shot `TabFM` (`AI.PREDICT` two-table context/prediction call) or the domain heuristic (`maker_alarm`, LACE score, top-margin rule).
  - **Retrieval & Ranking (`search-conversion`, `recommender`):** Compare semantic/hybrid retrieval (`AI.GENERATE_EMBEDDING` + `VECTOR_SEARCH` / `MATRIX_FACTORIZATION`) against lexical keyword match or top-seller popularity baseline.
  - **Causal / MMM (`marketing-measurement`):** Compare adstock + Hill saturation regression / Meridian against naive unadjusted linear regression (`LINEAR_REG`) and validate against `geo_holdout_experiment`.

## 🧭 4. Two-Turn Design Steering & Split-Location Rule
- **Turn 1 -> Turn 2 Design Refinement:** In Step 3 (Agentic Design), first profile the actual BigQuery tables to surface data gaps or leakage traps, then refine `DESIGN.md` with an `## Architect's Design Audit & Steering Log` section recording at least 2 agent assumptions caught and corrected before any training job runs.
- **Split-Location Architecture (3 Independent Service Regions):** Keep all BigQuery datasets (`citibike_tier0`, `l400_ds_work`, `pdm_workshop`, `mmm_workshop`) and the data bucket in `US` multi-region (`bigquery-region: "US"` in `agent-config.json`) so joins against `bigquery-public-data` require zero copies. Regional compute services are configured independently:
  - `bigquery-region: "US"`: BigQuery SQL, `AI.FORECAST` (`TimesFM 2.5`/`3.0`), `AI.PREDICT` (`TabFM`), and `BQML` (`ARIMA_PLUS`, `ARIMA_PLUS_XREG`, `BOOSTED_TREE_*`, `RANDOM_FOREST_*`).
  - `spark-region` (`us-central1` default, or `us-east1` / `us-east4` / `us-west1` fallback): **Managed Service for Apache Spark (`Serverless -> Batches`)** PySpark batch & Spark Connect jobs (`gcloud dataproc batches submit pyspark`).
  - `vertex-ai-region` (`us-central1` default, or `us-east1` / `us-east4` / `us-west1` fallback): **Agent Platform (Vertex AI) Custom Jobs (`Models -> More services -> Training -> Custom jobs`)** (`gcloud ai custom-jobs create`) and Model Registry.

## 🧩 5. Pre-Trained Foundation vs. Custom-Trained Models Across Tiers 0–3
Pre-trained foundation models (`TimesFM` & `TabFM`) are **additive options across Tiers 0–3** — they **never replace** custom-trained models when data scale, feature count, explainability, or causal structure require custom fitting:
1. **Tier 0 & Tier 1 (In-Warehouse BigQuery SQL):**
   - **Pre-Trained Option (`AI.FORECAST` `TimesFM 2.5`/`3.0` & `AI.PREDICT` `TabFM`):** Zero-DDL inference for time-series (`<= 2,048` context points in `TimesFM 3.0`, including **`TimesFM 3.0` with covariates** `target_cols`, `past_covariate_cols`, `future_covariate_cols`) and bounded tabular splits (`<= 50` feature cols, `<= 10` classes, `~5,000–8,000` practical training context rows on on-demand slots in `TabFM`).
   - **Custom-Trained Option (`BQML CREATE MODEL`):** Required for full multi-million-row tables, `> 50` features, `> 10` classes, deterministic repeatable scoring, reusable `TRANSFORM(...)` pipelines, `ML.EXPLAIN_PREDICT` / `ML.EXPLAIN_FORECAST` attributions, and custom weights (`ARIMA_PLUS`, `ARIMA_PLUS_XREG`, `BOOSTED_TREE_REGRESSOR`, `RANDOM_FOREST_REGRESSOR`, `BOOSTED_TREE_CLASSIFIER`, `MATRIX_FACTORIZATION`, `LOGISTIC_REG`, `LINEAR_REG`).
2. **Tier 2 & Tier 3 (Python, Managed Spark & Low-Latency Endpoints):**
   - **Pre-Trained Open-Weight Option (Hugging Face / Vertex AI Model Garden):** Both **`TimesFM 3.0` (`google/timesfm-3.0-pytorch`, `google/timesfm-2.5-200m-pytorch`)** and **`TabFM` (`google/tabfm-1.0.0-pytorch`, `google/tabfm-1.0.0-jax`)** can be downloaded and hosted on **Vertex AI Endpoints**, **Cloud Run**, or **`Dataflow RunInference`** for **sub-100ms real-time inference** (bypassing BigQuery's `30–95s` batch TVF latency) or custom GPU batch runs.
   - **Custom-Trained Option (`Vertex AI Custom Training`, `Managed Service for Apache Spark / Serverless Spark`, `BigFrames bigframes.ml`):**
     - **Pure Python Statistical & ML Forecasting:** Classical statistical time-series models (**Theta** via `statsmodels.tsa.forecasting.theta.ThetaModel` / `statsforecast` `AutoTheta`, and **Holt-Winters** via `statsmodels.tsa.holtwinters.ExponentialSmoothing` / `AutoETS`), global tabular ML over horizon-safe lags (`lag_30d`, `lag_37d`, `rolling_7d_lag30`), `station_customer_share` ratio, `capacity`, `lat/lon`, and weather/holidays (`XGBoost`, `LightGBM`, `scikit-learn` `RandomForestRegressor` — scoring established and cold-start stations alike), hierarchical reconciliation (`Bottom-Up` / `Top-Down` / `MinT`), and **BigQuery SQL Ensembling** across runtimes.
     - **Survival, Causal & Ranking:** Right-censored survival (`CoxPH` / Weibull), causal Bayesian MMM (`Meridian` adstock/Hill saturation), and two-tower retrieval + cross-encoder reranking.

## ☁️ 6. Zero Local Compute Rule & Managed Cloud Runtimes
- **Strict Ban on Local VM Model Training:** Never download training tables to the local Cloudtop VM via `.to_pandas()`, never fit local `scikit-learn`/`lightgbm`/`xgboost`/`statsmodels` models in Cloudtop memory, and never use `SparkSession.builder.master("local")` (only tiny `<= 20`-row aggregated evaluation summary tables may be pulled locally to write `artifacts/eval_metrics.json`).
- **Mandatory Managed Google Cloud Runtimes:**
  1. **Tier 1 & In-Warehouse Benchmark (`@skill:bigquery-data-science` + `@skill:bigquery-ml` + `@skill:bigquery-ai`):** Fit `<project>.<dataset>.challenger_xgb` (or problem-specific `CREATE OR REPLACE MODEL ...`: `ARIMA_PLUS`, `ARIMA_PLUS_XREG`, `BOOSTED_TREE_REGRESSOR`, `RANDOM_FOREST_REGRESSOR`, `BOOSTED_TREE_CLASSIFIER`, `LOGISTIC_REG`, `LINEAR_REG`, `MATRIX_FACTORIZATION`) or `AI.FORECAST` (`TimesFM 3.0` with covariates) / `AI.PREDICT` inside BigQuery (`bigquery-region: "US"`, inspectable under BigQuery Studio `Models` tab).
  2. **Tier 2 Managed Service for Apache Spark (`Serverless -> Batches`, `@skill:gcp-spark`):** Execute distributed PySpark jobs in `spark-region` via `gcloud dataproc batches submit pyspark <script.py> --project=<project_id> --region=<spark-region> --version=2.3 --deps-bucket=gs://<bucket>`, polling to `state == "SUCCEEDED"` and writing `<dataset>.spark_challenger_preds`.
     - **Spark Time-Series Co-Location Pattern (No Executor Wait Time):** Read `l400_ds_work.feature_spine` via `spark-bigquery` (`readDataFormat="ARROW"`), hash `(series_id, model_id)` into deterministic buckets (`pmod(hash(...), n_buckets)`), set `spark.sql.shuffle.partitions = 3 * n_buckets` and `spark.sql.adaptive.coalescePartitions.enabled = false`, and execute `groupBy(bucket).applyInPandas(fit_and_forecast, schema=...)` alongside distributed `SparkML` (`GBTRegressor` / `SparkXGBRegressor`).
  3. **Tier 2 Agent Platform Custom Jobs (`Models -> More services -> Training -> Custom jobs`, `@skill:bigquery-mlops`):** Submit pure Python training & reconciliation scripts (`statsmodels` Theta / Holt-Winters, `xgboost`, `scikit-learn`, `MinT`) in `vertex-ai-region` via `gcloud ai custom-jobs create` using `machineType: e2-standard-4` (never `n1-standard-4`), `imageUri: python:3.11-slim`, and `serviceAccount: <PROJECT_NUMBER>-compute@developer.gserviceaccount.com`, polling to `state == "JOB_STATE_SUCCEEDED"` and writing `<dataset>.vertex_challenger_preds`. For Pass 2 **Tier 2**, run **both** the Serverless Spark batch and the Agent Platform CustomJob (plus `challenger_xgb`), verify both succeed, and blend/compare their holdout outputs in `<dataset>.eval_comparison` and `artifacts/eval_metrics.json`.
